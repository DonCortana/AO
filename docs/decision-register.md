# Atlas Decision Register

Append-only. A decision is added here, never edited after acceptance — a
reversal is a new decision that references the one it retires. Execution
Plan Technical Lane step 1 requires this file exist in the repo alongside
the methodology, operating system and execution plan.

Per Methodology §10 (Governing Rule): "No methodology version becomes
client-active from convenience, provider deprecation or software limitation
alone. The decision is documented first, then implemented, then applied
forward." Decisions are documented before implementation; any exception is
noted in the row itself.

| D-037 | 2026-08-27 | The §6.2 hierarchical paired bootstrap is implemented on the standard library's `random.Random` (Mersenne Twister) with a caller-supplied seed that is required, not optional, and is returned with the result for storage alongside the score row. No numpy, scipy or statsmodels dependency is added. Reason: a client-facing interval must be exactly reproducible from stored inputs (§9 requires every score row carry its interval bounds and evidence references; §8.4 freezes v1.0 only once "the score engine reproduces hand calculations"). `random.Random` is documented as reproducible across Python versions for a given seed, whereas numpy's `Generator` stream is explicitly not guaranteed stable across releases. Performance was measured rather than assumed and does not force a tradeoff: 10,000 resamples over 40 prompts x 4 platforms x 5 replicates completes in 1.6 s in pure Python (3.3 s at 80 prompts). The 2.5th/97.5th percentiles use linear interpolation between closest ranks, verified against `numpy.percentile(..., method="linear")` to 7.1e-15 over 200 random arrays x 5 quantiles. The Wilson interval used for Mention Rate and Top-3 Rate is likewise hand-implemented, verified against `statsmodels.stats.proportion.proportion_confint(method="wilson")` to 1.1e-16 across 19 cases including the 0/n, n/n and n=1 boundaries; z is pinned to 1.959963984540054 rather than 1.96 (a ~6e-6 difference on the bound) so it is exactly the standard normal 0.975 quantile. | Active |
| D-038 | 2026-08-27 | Methodology §6.2 specifies the hierarchical paired bootstrap in one sentence that is under-determined in four ways, each of which changes the reported interval. Resolved before implementation. (a) **What is paired:** one prompt-ID draw is made per resample and applied to *both* periods, which is what "Baseline and validation are recomputed within the same bootstrap draw" requires; replicate observations are then resampled independently within each period, because replicate 3 of a baseline run and replicate 3 of a validation run are not the same unit and pairing them would be fiction. This is load-bearing and was measured by controlled A/B against the shipped implementation — identical data, identical seed, 10,000 resamples, the *only* difference being whether one prompt draw feeds both periods (`movement.py:199-208`) or each period draws independently. Median 95% CI width at 40 prompts x 4 platforms x 5 replicates: **4.93 AVS points paired vs 15.82 unpaired, a 3.2x inflation**; the ratio holds across scales (2.4x at 12 prompts, 2.9x at 20, 3.3x at 80). On one representative cycle the paired interval is (+4.62, +9.61), which excludes 0 and returns Improvement, while the unpaired interval on the same data is (-1.12, +15.31), which includes 0 and can only return Inconclusive — so the choice decides whether an MRC-5.0 movement is reportable at all. (An earlier uncontrolled estimate put the unpaired width near 26 points; it came from a diagnostic that also varied tier count and the pairing of the underlying data, and is superseded by the A/B figures above.) (b) **Repeated prompts:** a prompt drawn k times in one resample gets k independent replicate resamples, the standard hierarchical treatment. (c) **Empty cells:** a prompt-platform cell holding no scoreable replicate in a given draw is dropped from that PlatformScore's intent-weighted mean and its weight removed from the denominator, rather than imputed as zero — a technical or parsing gap is never scored as an absence (Operating System §1). (d) **Unpaired prompts:** the resampling frame is the intersection of prompts observed in both periods; a prompt present in only one period cannot contribute to a paired delta, is excluded from the frame, and is reported in the result so the exclusion is visible rather than silent. Additionally the reported point-estimate delta is computed from the observed data, not taken as the mean of the bootstrap distribution, and "95% CI excludes 0" is evaluated strictly (a bound of exactly 0.0 includes 0, so the verdict is Inconclusive). Interval calibration was checked by simulation against a known population delta: 98.0% coverage at a nominal 95% over 300 simulated cycles — slightly conservative, the safe direction for a reporting threshold. | Active |

| D-045 | 2026-08-27 | The unit of analysis for every §8.4 agreement statistic is the **prompt-platform cell**, not the replicate. Layer A (n=5, §6.1) and Layer B (n=3 target, §8.3) are each collapsed to one cell-level binary mention judgment by majority vote before raw agreement, Cohen kappa or Spearman rho is computed. Reason: §8.4 states three thresholds and never names their denominator, in the same way §6.2 stated the bootstrap and never named its pairing — the D-038 problem, in a new section. The two readings are not close. Tie handling: both replicate counts are odd by design, so majority does not tie in the intended case; if an operational shortfall (a failed call, an abandoned capture) drops a cell to an even count, the tie resolves to `absent` and the cell is logged for manual review — never silently broken toward mention, which would flatter agreement, and never silently dropped, which would shrink the denominator invisibly. | D-046 | 2026-08-27 | A Frozen Core prompt flagged non-diagnostic under §7 (returning the client in >90% of baseline replicates across every eligible platform) **stays in the frozen set with no rebaseline**, is excluded from the AVS intent-weighted mean, and is reported separately as an entity-accuracy check. The exclusion is conditional on the flag actually tripping against baseline data — it is never written into the prompt set as an unconditional property of a prompt. Reason: §7 says such a prompt "is flagged non-diagnostic" and then stops, defining no consequence. That would be deferrable except that §7 also makes set membership immutable — "Prompt changes that alter intent, entity, tier or set membership require a major prompt-set version and a new baseline" — so discovering the flag at baseline and reacting by removing the prompt would invalidate the entire calibration run that discovered it. The rule therefore has to exist before the set is frozen, not after the data arrives. Retention-with-exclusion is the only reading that satisfies both halves of §7 at once: membership is untouched, so no rebaseline is triggered, while a prompt carrying no discriminating signal stops contributing to a score that is supposed to measure discrimination. The separate report is not a consolation: a saturated branded prompt is the instrument that surfaces `entity_conflict` — wrong-entity and name-collision behaviour, which §4.1 routes to P3 rather than AVS — so the prompt keeps doing the job it is actually good at. Conditionality is the load-bearing half of this decision. Writing "excluded from AVS" into a prompt's definition at authoring time would prejudge an empirical result, would make the AVS denominator depend on an author's expectation rather than on observed replicate behaviour, and would silently change the score if a prompt that was expected to saturate turned out not to. The flag is computed from baseline observations, stored, and only then does it exclude. A prompt that stops saturating in a later cycle stops being excluded, and the change is visible in the stored flag rather than requiring a prompt-set edit. | Active |
| D-047 | 2026-08-27 | Rank collapse for a co-mentioned prompt-platform cell is the **median rank across that cell's mentioned replicates**, computed per layer, on the same cells D-045 collapses for mention agreement. Reason: D-045 fixed the unit of analysis as the cell and specified the *mention* collapse (majority vote) but not the rank collapse, and Spearman rho needs one rank value per cell per layer — majority vote does not produce one. The gap was found while implementing D-045, not in review, and it changes a reported §8.4 statistic, so it is settled here rather than left to the code. Median is chosen because rank is ordinal: a position is a place in a list, not a quantity, so an arithmetic mean over positions asserts a spacing the data does not carry (the distance from rank 1 to rank 2 is not the same kind of thing as the distance from rank 9 to rank 10, and §4.1's own RPV table prices those gaps very differently — 1.00 -> 0.80 versus 0.25 -> 0.25). Median is additionally robust to a single outlying replicate, which matters at n=5 and n=3 where one anomalous deep placement would drag a mean several positions and misrepresent a cell that was otherwise stable. The choice is deliberately low-stakes by construction: the collapsed ranks feed only Spearman, which re-ranks its inputs before correlating, so **only relative ordering between cells survives the collapse** — any monotone-preserving summary of a cell's replicates would give the same rho, and median is the one that is also a real observed position in the odd-count case. Rejected: the mean (imposes interval spacing on ordinal data); the best (minimum) rank (systematically flatters the client by reporting its luckiest replicate); the modal rank (undefined or arbitrary whenever replicates disagree, which is the normal case). Even-count ties resolve as `statistics.median` does, by averaging the two middle positions — a non-integer cell rank is acceptable precisely because only ordering is used downstream, and no client-facing number reports a cell rank directly. Replicates that were not mentions contribute no rank and are excluded from the median rather than entering it as a sentinel; a cell whose majority judgment is absent carries no rank at all. This decision changes how a cell's rank *value* is derived and nothing about the statistics themselves — the kappa and Spearman implementations, and their verification against sklearn 1.9.0 and scipy 1.18.1 recorded under D-045, are untouched. | Active |

## Adding a decision

1. Determine version treatment per Methodology §10 (patch/clarification vs.
   new baseline vs. major methodology version vs. operating update).
2. Add a row here with the next sequential D-xxx ID, dated, with the
   decision stated in full — not just a reference to a discussion.
3. Only then implement it in the methodology/operating docs and/or code.
4. If the decision retires an earlier one, mark the earlier row's Status
   column "Retired by D-xxx" — do not delete or rewrite it.
